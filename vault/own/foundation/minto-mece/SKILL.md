# MECE 与分组思考

用互斥穷尽把问题切开，再用正确顺序排列；归纳向上时写出**具体概括**，禁止空洞标题。

服务金字塔的横向质量；也用于解题分析的预先组织。

## 何时使用

- 方案分类、原因拆解、范围界定、议题树  
- 「这几条叠了 / 漏了」  
- Review 判定横向不 MECE 或顺序无理  

切好的组回到 `minto-pyramid` 当 Key Line/下层；开场用 `minto-scqa`。

## 工作流

```
MECE Progress:
- [ ] 1. 写清「正在切的整体」是什么
- [ ] 2. 选切割方式：结构 / 流程 / 属性归类
- [ ] 3. 列出互斥部分，查重叠
- [ ] 4. 查穷尽（相对目标是否够用）
- [ ] 5. 定顺序：时间 / 结构 / 重要性
- [ ] 6. 为每组写非空概括句
- [ ] 7. 必要时下钻一层逻辑树
```

## MECE

**Mutually Exclusive（互斥）**：部分之间不重叠。  
**Collectively Exhaustive（穷尽）**：合起来覆盖你定义的整体。

实用原则：

- 先写清整体边界（「本季度获客下降的原因」≠「公司一切问题」）  
- 追求 **够决策的穷尽**，不必哲学上 100% 卡死产出  
- 发现重叠：改定义或合并；发现漏洞：补一类或扩大/缩小整体  

## 三种切割与顺序（明托）

| 分析活动 | 得到的组 | 顺序 |
|----------|----------|------|
| 揭示过程 | 步骤/因果链上的环节 | **时间序** |
| 可视化整体结构 | 组成部分 | **结构序**（且 MECE） |
| 按某特征归类 | 类别 | **重要性/程度序** |

自检：顺序是否 **反映你当初怎么切出来的**？若只能「随便排」，分组可能有问题。

## 逻辑树 / 议题树（要点）

- 顶节点 = 要回答的问题或要解释的现象  
- 每一层用同一种切割逻辑（不要一层里混「原因+部门+时间」）  
- 子节点合起来应回答父节点  
- 到「可验证/可行动」的叶子再停（数据、实验、决策选项）  

常见用途：

- 诊断：现象 → 互斥原因分支  
- 方案：目标 → 互斥策略选项（再比）  
- 工作计划：交付物结构拆分  

## 归纳概括：禁止智力空白

坏：

- 「有三个问题」  
- 「需要做若干改进」  
- 「存在一些风险」  

好：

- 点明 **共同效应** 或 **具体结论**  
- 让读者不看下层也知道「所以怎样」  
- 下层条目应能被这句真正概括（以上统下）  

对行动组：概括行动合起来达到的效果，而不是「采取了三个行动」。

## 输出格式

```markdown
# MECE / 分组令

**整体（被切开的对象）**: …
**切割方式**: 结构 / 流程 / 归类
**目标用途**: 诊断 / 方案 / 表达 Key Line

## 分组（互斥列表）
1. … — 定义边界: …
2. …
3. …

## 穷尽检查
- 已覆盖: …
- 可能漏洞: …（补/刻意排除及理由）
- 重叠风险: …（如何消解）

## 顺序
- 规则: 时间 / 结构 / 重要性
- 排列: 1 → 2 → 3 …

## 概括句（非空）
- 对整组: …
- 对各组: 1.… 2.… 3.…

## 若下钻
### 1. …
- 1.1 …
- 1.2 …
```

## 反模式

- 「内部/外部」等万能二分却不定义边界，造成假 MECE  
- 同一层混多种切割维度  
- 为凑三条而生造空洞类别  
- 用「其他」桶装走所有难类（除非真是残差且声明）  
- 概括句复述「以下几点将讨论…」  

## 边界

- MECE 是思考工具，不是宗教；标出已知近似即可  
- 不代替专业领域模型；领域框架可当作切割模板，仍要做互斥穷尽检查  
- 表达层塔形交付交回 `minto-pyramid`
