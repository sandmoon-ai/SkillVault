# 搭建金字塔（写作的逻辑）

先想清塔，再写字。规则：任一层次的思想概括其下；同组思想同类且有逻辑顺序；表达时结论在上。

## 何时使用

- 从零搭报告/提案/幻灯片逻辑
- 结论埋在文末，要改成先给答案
- Review 判定纵向/横向结构崩

序言细做 → `minto-scqa`；分组 MECE 细做 → `minto-mece`。成文 → `kaku-draft`。

## 工作流

```
Pyramid Progress:
- [ ] 1. 定读者与必须回答的核心问题
- [ ] 2. 写出塔尖一句（答案）
- [ ] 3. 列出 Key Line（2–4 条支撑，答「为何/如何」）
- [ ] 4. 每条下再拆一层证据/子点
- [ ] 5. 查纵向问答 + 横向演绎/归纳 + 顺序
- [ ] 6. （可选）自上而下走读；或自下而上归纳后仍输出为塔
- [ ] 7. 输出金字塔令，再允许写正文
```

## 三条铁律

1. **以上统下**：任一层次的陈述必须是对下一层的概括  
2. **组内同类**：同一组思想属同一逻辑范畴（能共用一个复数名词）  
3. **组内有序**：时间序 / 结构序 / 重要性序（与如何分析出来的一致）  

大脑一次难稳稳抓住很多互不相关的点 → **分组后再表达**。

## 纵向：问答对话

读者每读一点，心里会冒出疑问；你的下一层必须答这个疑问。

典型疑问：

- 为什么？（理由）  
- 如何做？（步骤）  
- 何以见得？（证据）  
- 哪几部分？（结构）  

自检：把上层当问句，下层当答——是否答到点上？

## 横向：演绎或归纳（只能居其一）

### 演绎（Deductive）

链式：大前提 → 小前提 → 因此结论。  

- 适合严密论证、读者接受前提时  
- 书面呈现时，有时仍把 **结论提作塔尖**，演绎链放在支撑层（避免读者在链尾才见到答案）  

### 归纳（Inductive）

若干 **同类** 思想 → 向上概括共同点/共同效应。  

- 商业沟通更常用  
- 概括句必须具体，禁止「有三点」式空白断言  
- 点数宜少而紧（常见 Key Line 约 2–4）  

## 同组顺序

| 分析来源 | 顺序 |
|----------|------|
| 过程/因果步骤 | 时间序 |
| 整体的部分 | 结构序（且近 MECE） |
| 按某属性归类 | 重要性/程度序（强→弱等） |

顺序错了，往往暴露分组本身有问题——回去重分，而不是硬排。

## 自上而下 vs 自下而上

- **表达/交付**：自上而下（先塔尖与 Key Line）  
- **整理素材**：可自下而上归类提炼，但最终仍画成塔再写  
- 切忌边写边找中心思想  

## 幻灯片/演示要点

- 一页一个思想（对该页标题即主张）  
- 页标题是塔中的一句，不是主题词  
- 页面结构反映 Key Line，避免无逻辑的装饰拼贴  

## 输出格式

```markdown
# 金字塔令

**读者核心问题**: …
**塔尖（Answer）**: …

## Key Line
1. …（答：…）
2. …
3. …

## 下一层（节选）
### 1. …
- …
- …

## 横向类型
- Key Line 层: 归纳 / 演绎
- 顺序规则: 时间 / 结构 / 重要性

## 纵向自检
- 上层疑问 → 下层是否回答: ✅/备注

## 明确不写进主塔
- …（放附录）
```

## 反模式

- 按发现故事的顺序写（日记体）当论证  
- 同组混进「原因+步骤+感想」  
- Key Line 十条以上且不归并  
- 标题用「情况说明」「其他」等非思想标签  

## 边界

- 不编造支撑事实；缺料标待补  
- 与 `kaku-design`：kaku 管消息/读者/大纲流程；本 skill 管大纲内部的逻辑塔形  
- 开头叙事接塔尖用 `minto-scqa`
