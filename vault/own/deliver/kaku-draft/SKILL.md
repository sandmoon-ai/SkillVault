# ドラフトを書く（Step5）

按设计图快写第一稿。心态：**写了就可以扔**——完美主义停在设计之后、推敲之前。

前置：已有 `kaku-design` 产出的メッセージ・読み手・アウトライン。没有设计就先回去设计。

## 何时使用

- 大纲已定，需要正文  
- 用户卡在「第一句必须完美」  
- Review 判定「设计有了，正文没有/没写完」

写完后交 `kaku-revise`，不要在草稿阶段反复雕句。

## 工作流

```
Draft Progress:
- [ ] 1. 确认设计令（消息、读者、大纲）仍有效
- [ ] 2. 约定：本轮只求完整，不求漂亮
- [ ] 3. 按大纲顺序写，一节写完再下一节
- [ ] 4. 缺证据处用【待补：…】占位，不编造
- [ ] 5. 通读一遍仅修「断句级」硬伤，不重构
- [ ] 6. 交修订清单入口给 kaku-revise
```

## 核心心态：捨てるつもりで書く

- 第一稿是粘土，不是展品  
- 「一次写对」会阻塞产出；本书强调先有稿再磨  
- 允许丑、允许重复、允许临时句——**不允许没写完就回头改第一节措辞三小时**

## 起草规则

1. **跟着大纲走** — 节标题即主张；段内不跑题  
2. **先结论后展开**（除非设计令规定叙事顺序）  
3. **一段一意** — 新意新段  
4. **导入先写清「为何读」** — 可用朴素句，稍后推敲再亮  
5. **读者任务优先** — 删掉只对作者有意义的过程叙述  
6. **占位诚实** — `【待补：来源/数据】`，不伪造权威  

## 速度技巧

- 时间盒：按节限时，到点进入下一节  
- 不会表达时写「口头版」：`（大意：应先做 A，因为成本）` 再继续  
- 引用/数字稍后粘；先留钩子  
- 不要边写边查同义词；那是 Step6–7 的事  

## 草稿最低完成线

- [ ] 导入 → 本体各节 → 收束 都有文字  
- [ ] 一句消息在文中可被指认（导入或收束出现）  
- [ ] 大纲无整节空白  
- [ ] 待补项集中列出  
- [ ] 尚未做「文学性」润色（正常）  

## 输出格式

```markdown
# ドラフト（可扔）

**メッセージ**: …
**读者**: …
**状态**: 初稿完整 / 缺节: …

## 正文
…

## 占位 / 待补
- …

## 作者笔记（不进终稿）
- 写时卡点: …
- 疑似应调整大纲的地方: …（交 revise/design 决定，草稿内不擅自大改）
```

若发现大纲错误：

- **小错**（节内顺序）：草稿里微调并备注  
- **大错**（消息变了/读者错了）：**停写**，回 `kaku-design`，不要用堆字掩盖  

## 反模式

- 写三句就推敲字体级措辞  
- 无大纲自由联想成文  
- 用套话填满「背景」节假装进度  
- 把待补证据写成确定事实  

## 边界

- 不产出「终稿口吻」的包装；丑但是完整 > 美但是半篇  
- 代码注释/API 文档若套用：同样先大纲后草稿，术语准确优先于文采  
- 下一步：`kaku-revise`
