# 書く前の设计（Step1–4）

动笔前完成设计。7 Step 里前四步决定上限；句子漂亮救不了空洞设计。

完整顺序：メッセージ → 読み手 → アイデア → アウトライン →（draft）→（revise）。

## 何时使用

- 「第一句写不出来」
- 要写报告/企画/说明/邮件/职务経歴叙事，但结构未定
- Review 判定缺消息、缺读者、缺大纲

设计完成后交 `kaku-draft`；不要在本阶段抠金句。

## 工作流

```
Design Progress:
- [ ] 1. メッセージを定める
- [ ] 2. 読み手を分析する
- [ ] 3. アイデアを集める
- [ ] 4. アウトラインをつくる
- [ ] 5. 用三问自检后再允许起草
```

## Step1 メッセージを定める

消息 = 为填补某个 **ギャップ** 而必须传达成的那句话。

写清：

1. **ゴール**：读者读完应知/应信/应做的状态  
2. **现状**：读者现在知道什么、卡在哪  
3. **ギャップ**：二者之差  
4. **一句メッセージ**：填补缺口的主张（可验证、可导航全文）

检验：

- 能否写在便利贴上？
- 删掉一半段落，消息是否仍成立？（若否，段落在拖累）
- 避免主题词冒充消息（坏：「关于市场」；好：「应先做 A，因为 B」）

## Step2 読み手を分析する

沟通成败由 **读者侧评价** 决定。

至少回答：

| 问 | 写下 |
|----|------|
| 谁是主要读者？还有次要读者吗？ | |
| 谁拍板/谁会转发？ | |
| 他们要完成什么任务？ | |
| 已有什么信息？缺什么？ | |
| 误解风险是什么？ | |
| 语气与距离：简报 / 说服 / 请示 / 同步？ | |
| 阅读情境：手机速览 / 会上投影 / 打印精读？ | |

导出约束：

- **必给信息**（没有就无法行动）  
- **可附录信息**（别堵在主路径）  
- **禁忌**：行话、雷点、过长前置  

邮件尤其注意距离感：对谁该短、对谁该有上下文。

## Step3 アイデアを集める

先发散、后收敛——服务消息，不是炫博学。

1. **发散**：论点、事例、数据、反例、步骤、风险（不评判）  
2. **标注**：每个点子如何支撑メッセージ（撑 / 弱 / 无关）  
3. **丢弃**：无关与弱支撑；「质量 ≤ 设计」从这里开始做减法  
4. **补洞**：主张旁是否缺数据或论拠？列出待查项  

成套意识：**主张 — 论拠 — 数据/事实**。缺一就标缺口，不假装完整。

## Step4 アウトラインをつくる

大纲是文章的设计图；无图不开建。

### 通用骨架

```
1. 导入（前書き）
   - 为何现在读 / 读完得到什么 / 一句消息预告
2. 本体（按读者任务排序，非按你发现顺序）
   - 点1（主张 → 支撑）
   - 点2 …
3. 收束
   - 结论重申消息
   - 行动/下一步（若需要）
```

### 排序原则

- 读者决策路径优先（先结论后细节，或先问题后方案——按文类选一种并贯彻）  
- 一段一意；同级标题平行  
- 导入决定「读不读」：写清钩子与收益，禁空话开场  

### 大纲粒度

每节用 **短语主张** 而非「背景」「其他」：

- 坏：`3. 补充说明`  
- 好：`3. 若不做 A，下季度成本仍升`

## 自检（过关才进草稿）

- [ ] 一句メッセージ固定  
- [ ] 读者与必给信息固定  
- [ ] 点子已筛选并挂在消息下  
- [ ] 大纲每节都服务消息  
- [ ] 导入能独立说服人「值得读」  
- [ ] 已知证据缺口已列出（不装懂）  

## 输出格式

```markdown
# 文章设计令

## メッセージ
- ゴール: …
- 现状: …
- ギャップ: …
- 一句消息: …

## 読み手
- 主读者: …
- 任务: …
- 必给信息: …
- 语气/距离: …
- 情境: …

## アイデア（已筛选）
| 点子 | 支撑消息？ | 主张/论拠/数据 | 备注 |
|------|------------|----------------|------|
| | | | |

## 待补证据
- …

## アウトライン
1. 导入: …
2. …
3. …
N. 收束: …

## 明确不写
- …
```

## 反模式

- 先写两千字再找中心思想  
- 大纲只有「背景-内容-总结」空壳标题  
- 读者写成「所有人」「公司」  
- 把收集到的材料全塞进正文  

## 边界

- 不编造数据；缺口进「待补」  
- 职务経歴书等例题：同样走消息（录用方要什么）→ 读者（人事/现场）→ 事例点子 → 大纲  
- 下一步固定调用 `kaku-draft`，本 skill 不产出成稿美文
