# Krug Scan & Copy（为扫描设计）

把界面改成可扫读、选项无脑、文字能删则删。服务「别让我思考」，不是文学润色。

## 何时使用

- 页面像说明书、标题不分层、按钮文案含糊
- 用户说太长、读不下去、选项看不懂
- Review 已指出扫描/文案问题，需要落改

整页导航/首页结构 → `krug-navigation`；仅审不改 → `krug-review`。

## 工作流

```
Scan Progress:
- [ ] 1. 定本页任务与必留信息
- [ ] 2. 建视觉层级（谁重要、谁归谁、谁同类）
- [ ] 3. 标明可点物，降噪声
- [ ] 4. 改选择标签（互斥、口语、无谜语）
- [ ] 5. 删字：先砍一半，再砍一半
- [ ] 6. 格式化为可扫描文本
```

## 用户真实行为（设计前提）

1. **扫，不读** — 找任务相关词、兴趣词、触发词
2. **满意即可（satisfice）** — 选第一个「够像」的，不最优求解
3. **勉强应付（muddle through）** — 很少读说明；能点通就不学模型

因此：自解释 > 帮助文档；清晰标签 > 聪明文案。

## 广告牌法则：视觉层级

让页面自己「大声说出」结构：

1. **重要性** — 更重要 → 更显眼（尺寸、字重、位置、对比）
2. **归属** — 相关的成组；标题贴内容；嵌套表示从属
3. **同类** — 同级元素同一样式，别一排五种强调

检查：

- 眯眼三秒，能否说出主标题与主 CTA？
- 是否到处都在「最重要」（等于都重要）？
- 分隔是否靠留白/对齐，而不是到处加框线噪音？

## 可点性与噪声

**可点性必须一眼可知：**

- 链接/按钮有稳定视觉语言（形状、颜色、下划线策略一致）
- 避免「整块像可点、只有小字可点」的陷阱
- 图标按钮要有可理解标签或文案邻近

**降噪声：**

- 动画、徽章、边栏促销、多重高亮会稀释主任务
- 三层噪声：嚷嚷的东西、本可安静的东西、几乎看不见却占位的东西——能删就删、能弱就弱

## 无脑选择（动物 / 植物 / 无机物）

每个分叉应：

- **互斥**：选项之间边界清楚
- **穷尽任务路径**：用户能对号入座
- **用词来自用户语言**，不是内部架构名
- **避免聪明但不清楚**的双关、隐喻导航

坏：`解决方案 | 赋能 | 生态`  
好：`定价 | 文档 | 联系销售`（按真实站点任务改）

点击次数可以多；**每一次犹豫**才贵。

## 第三定律：省略多余的文字

口诀：**删掉一半，再删掉剩下的一半。**

优先砍：

1. **愉快的废话** — 欢迎词、自我介绍段、空洞品牌宣言
2. **说明书** — 若界面自解释，删「请点击下方按钮以…」
3. **重复**：标题已说的，正文别再说一遍

保留：

- 完成任务必需的词
- 建立信任的最少证据（若任务需要）
- 法律/风险必要披露（可折叠或次级，但不伪造消失）

改写手法：

- 长段 → 短段 + 小标题 + 列表
- 名词套名词 → 动词+对象的动作句
- 「点击这里」→ 链上写目标本身（「查看定价」）

## 扫描友好的文本格式

- 有意义的小标题（可当目录扫）
- 短段落（一段一个点）
- 列表承载并列信息
- 关键词/关键短语可凭样式扫到（但别整页加粗）
- 开头句给结论，细节往后放

## 输出格式

```markdown
# Scan / Copy 改稿

**页面任务**: …
**必留信息**: …

## 层级令
- 主标题 / 主 CTA: …
- 次级块: …
- 弱化/删除: …

## 选择标签（若有）
| 原 | 改 | 理由 |
|----|----|------|
| | | 互斥/用户语言/去谜语 |

## 删字对照
### Before
…
### After（目标：明显更短）
…

## 扫描格式调整
- …
```

若直接改 UI 代码：同步层级 token（标题级、按钮主次），避免只改文案不改视觉权重。

## 反模式

- 为 SEO/品牌把首屏写成专题文章
- 用俏皮文案牺牲可预测性
- 「字少了就不专业」——专业来自清楚，不是来自字数
- 把所有字同等加粗/高亮

## 边界

- 不编造产品能力；不确定的承诺标为需产品确认
- 法律文案咨询合规，不擅自删实质条款
- 视觉排版美学细节可叠 `tsutawaru-typography` / `tsutawaru-layout`
