# デザインをはじめる前に（目的）

动手前先定目的。本书前提：**伝わるデザイン靠目的，不靠センス与玄学经验谈。**

无目的 → 禁止先选字体、配色、装饰。

## 何时使用

- 新开チラシ/スライド/企画書/通知/海报
- 「不知道该做成什么感觉」
- Review 判定目的缺失或媒介错配

目的令完成后：布局 → `nyumon-layout`；要素 → `nyumon-elements`。

## 工作流

```
Purpose Progress:
- [ ] 1. 文类与约束（尺寸、单色、品牌）
- [ ] 2. 读者是谁（场景、先验知识）
- [ ] 3. 核心传达（一句）
- [ ] 4. 期望反应（知/信/做/感）
- [ ] 5. 成功标准（3 秒/精读各看什么）
- [ ] 6. 媒介与信息优先级
- [ ] 7. 明确不做什么（反目的）
```

## 目的四问（必答）

1. **谁看？** — 具体人群，不是「所有人」  
2. **看什么情境？** — 路过远看 / 坐下精读 / 投影讲解  
3. **必须带走什么？** — 一句话信息（非主题词）  
4. **希望对方怎样？** — 记得、相信、到场、点击、转发、理解步骤…  

补问：

- 若只记住一件事，应是什么？  
- 若删掉一半内容，先删什么？  
- 品牌/合规有何硬约束？  

## 媒介匹配

| 媒介 | 目的侧重点 |
|------|------------|
| チラシ/掲示 | 3 秒抓住主信息 + CTA |
| スライド | 一页一意、远读 |
| 企画書 | 结论可扫、证据可钻 |
| 長文書類 | 見出し导航、连续可读 |
| Web 首屏 | 身份 + 主行动（可叠 `krug-navigation`） |

目的与媒介冲突时：**改内容优先级或改媒介**，不要靠堆装饰弥补。

## 从目的导出设计约束

把目的翻译成「后面章节的输入」：

| 导出项 | 例子 |
|--------|------|
| 主信息层级 | 主标题必须是主张，不是活动名堆砌 |
| 必现模块 | 时间/场所/价格/入口 |
| 语气 | 严谨 / 亲切 / 促销 |
| 视觉力度 | 强冲击 / 安静可信 |
| 图的角色 | 英雄情绪 / 证据 / 可无图 |
| 色印象方向 | 清爽/高档/活力…（细做交 haishoku） |

## 输出格式

```markdown
# デザイン目的令

**文类 / 尺寸**: …
**读者**: …
**情境**: 远看 / 精读 / 讲解

## 核心
- 一句传达: …
- 期望反应: …
- 只记一件事: …

## 优先级
1. 必留: …
2. 次要: …
3. 可删: …

## 设计约束
- 语气: …
- 力度: …
- 主 CTA / 行动: …
- 图: 要/不要；角色: …
- 色印象（方向词）: …
- 品牌/合规: …

## 成功标准
- 3 秒: …
- 精读: …

## 反目的（禁止）
- …
```

过关标准：陌生人只看目的令（不看稿）能想象出「这张东西在干什么」。

## 反模式

- 「先做漂亮再看放什么字」  
- 目的写成「提升品牌感」却无可观察行为  
- 同时要高档、狂欢、信息密度拉满  
- 用参考图代替目的（参考可有，但目的先行）  

## 边界

- 不写具体网格与色值（那是后续 skill）  
- 文案消息深层结构可叠 `kaku-design`；本 skill 管设计目的与视觉优先级  
- 与 `krug-*`：那边是用时认知；这边是制作前目的
