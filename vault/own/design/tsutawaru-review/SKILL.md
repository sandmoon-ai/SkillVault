# 伝わるデザイン Review

审阅资料是否「伝わる」。目标不是变炫，而是降低阅读负担、让信息结构一眼可读。

规则来源：《伝わるデザインの基本》的可执行要点。只输出可改问题与改法，不写审美空话。

## 何时使用

- 用户要求审幻灯片、企划书、Word/文档、图表、海报/チラシ
- 用户说「看起来乱 / 不专业 / 读不动 / 伝わらない」
- 用户提到余白、揃える、強弱、囲み、配色、ユニバーサルデザイン

若用户只要「做一版」而非审稿，仍先用本清单约束输出；深度排版规则可后续交给专用 skill。

## 工作流

复制并跟踪：

```
Review Progress:
- [ ] 1. 判定文档类型与阅读场景
- [ ] 2. Layout（5法则 + 视线 + 噪声）
- [ ] 3. Typography（字体・文字组・列表）
- [ ] 4. Charts / 図解 / 表
- [ ] 5. Color / 对比 / UD
- [ ] 6. 按类型补查（スライド等）
- [ ] 7. 输出问题清单（按严重度）
```

### 1. 判定类型

| 类型 | 阅读方式 | 额外关注 |
|------|----------|----------|
| スライド | 远距离、短时 | 字号、一页一意、少字 |
| 企画書 / 大判 | 近读+讲解 | 结构层级、图文对齐 |
| 文書（正文为主） | 连续阅读 | 行长、行間、段落、見出し |
| チラシ / 掲示 | 扫读 | 强アイキャッチ、信息优先级 |

先写清：**受众、介质（屏/印）、单色是否可能**。

### 2. Layout 检查（最优先）

按 5 法则扫一遍：

1. **余白** — 页边、块间距是否 suffocate？元素是否贴边、贴在一起？
2. **揃える** — 左缘/中线/列是否对齐？有无「差一点」的锯齿？
3. **グループ化** — 相关信息是否靠近？无关是否分开？标题是否贴着所属内容？
4. **強弱** — 标题/正文/注释是否有清晰层级（尺寸・粗细・色）？跳率是否太平？
5. **繰り返す** — 全篇标题位置、字号、色、图标风格是否统一？

再查：

- 视线是否大致左上→右下（或明确的 F/Z）？
- 是否囲み过多、圆角过多、装饰抢戏？
- 能否删掉不承载信息的线、底纹、阴影、渐变、立体？

### 3. Typography 检查

- 避免花哨/手写/过度装饰字体；正文优先高判读性字体
- 屏显：避免粗糙位图感强的旧ゴシック作为正文主力
- 和欧混排时，拉丁/数字是否突兀（字重、基线、字号）
- 数字强调是否清晰（数字大、单位小等，按信息优先级）
- 正文左揃え；避免无必要的两端揃え导致和文齿缝
- 行間是否过紧/过松；行长是否过长难扫读
- 箇条書き：标记统一、层级清楚、一项一事
- 禁止：文字变形拉伸、过度描边/阴影、斜体堆砌

### 4. Charts / 図解 / 表

**図形・囲み**

- 塗りと枠は基本どちらか一方（双重要素易脏）
- 角丸の丸みを統一；角丸乱用しない
- 去掉默认影・立体・渐变・夸张预设形状
- 矢印：柄と矢じりを歪めない；箭头本身不要抢过内容

**グラフ**

- 目的匹配：比较→棒、推移→折れ線、构成→円（慎用）等
- 去掉 3D、多余网格、无意义特效
- 标题尽量是结论句，而非「売上推移」这类标签

**表**

- 删多余框线；用留白/细分隔
- 数値は右揃え、文言は左揃え
- 宽表可隔行浅底；单元格内要有余白

### 5. Color / UD

- 色数克制（主色 + 强调 + 中性灰/黑 思路）
- 文字色与背景对比要够（浅灰字在浅底上是常见事故）
- 不只靠颜色传达状态（辅以形/字/线型）
- 打印可能单色时，检查灰度是否仍可区分

### 6. 按类型补查

**スライド**

- [ ] 一页一个主要信息
- [ ] 远看标题可读；正文不过密
- [ ] 全套マスター级统一（标题区、页边、色）

**企画書**

- [ ] 章节层级一眼可见
- [ ] 图与说明成组，不漂
- [ ] 背景照片不抢字、不降对比

**文書**

- [ ] 見出し层级稳定
- [ ] 段落间距 > 随意空行堆砌
- [ ] 长文行长可控（可段组）

**チラシ**

- [ ] 3 秒内能抓住主信息
- [ ] 行动信息（时间/场所/CTA）够强且位置稳定

## 输出格式

按严重度列出，每条必须可执行：

```markdown
# 伝わるデザイン Review

**类型**: [スライド/企画書/文書/チラシ]
**场景**: [屏/印、受众一句话]

## 总判
[1–2 句：最大阅读障碍是什么]

## 问题清单

### 🔴 Critical（先改）
1. **[现象]** → 违反：余白/揃える/…
   - 改法：…
   - 期望：…

### 🟡 Should fix
…

### 🟢 Nice to have
…

## 建议改稿顺序
1. …
2. …
```

规则：

- 先说「哪里妨碍理解」，再说「怎么改」
- 能引用 5 法则或具体禁则就引用；不要只说「更专业一点」
- 若用户附了文件/截图：指到具体页/区域；没有文件则给通用风险清单并索要样本

## 反模式（审稿时也避免自己犯）

- 为「好看」加阴影、渐变、立体箭头、彩色底纹
- 到处加囲み和圆角「框住安全感」
- 用颜色堆层级，却没有字号/字重差
- 把整页填满当「信息量大」
- 建议换一堆字体，却不解决对齐与余白

## 边界

- 不改写专业内容对错，只审信息呈现
- 品牌手册/既有设计系统优先于本书默认字体建议；冲突时注明「本书规则 vs 品牌约束」
- 需要深度重做版式时，先交 Review，再问用户是否进入改稿
