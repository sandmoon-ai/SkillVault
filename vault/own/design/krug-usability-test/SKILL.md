# Krug Usability Test（一天 10 美分）

用低成本、可重复的可用性测试找真问题。核心：**早测、常测、小样本、先修最痛的**。

## 何时使用

- 要一份可执行的测试计划/脚本
- 上线前或改版中想快速验证
- 团队在争论喜好，需要用观察打断空辩（呼应书中「农场主与牧牛人」）

测完要改界面结构 → `krug-navigation` / `krug-scan`；只基于截图静审 → `krug-review`。

## 关键原则（先对齐预期）

1. **测 1 个用户也比不测强**；早期 1 人 > 上线前 50 人
2. 半天能发现的问题，往往多过你一个月能修的 → **只排最严重的先修**
3. 目标是改进产品，不是做学术报告或证明某人错了
4. 可复用简易流程，胜过一年一次「豪华研究」
5. 人数：常见实用做法是 **轮次小样本（约 3 人量级）+ 多轮**，不是一次堆满人

## 工作流

```
Test Progress:
- [ ] 1. 定目的与要回答的问题
- [ ] 2. 写任务（具体、可完成、少剧透）
- [ ] 3. 准备原型/环境与成功标准
- [ ] 4. 招募：近似真实用户即可
- [ ] 5. 主持：想出声、少救场、少辩护
- [ ] 6. 记录：行为与障碍，非「喜不喜欢」
- [ ] 7. 复盘：严重度排序，只承诺修 Top 问题
- [ ] 8. 修好后安排下一轮短测
```

## 1. 定目的

写清：

- **这轮要学习什么？**（例：新访客能否完成注册并找到定价）
- **不在这轮争论什么？**（视觉喜好、品牌色除非阻碍任务）

## 2. 任务脚本

好任务：

- 有情境（「你打算…」）
- 有终点（可观察是否完成）
- **不泄露点击路径**（别说「右上角账户里…」）

模板：

```markdown
## 开场（主持人）
- 我们在测网站/App，不是测你
- 想到什么就说出来
- 没有错误答案；卡住是设计的问题
- 我会尽量少帮忙

## 背景（可选 30 秒）
你是… 想要…

## 任务
1. …
2. …
3. …

## 每任务观察点
- 起点点哪里？犹豫了吗？
- 走错哪？如何恢复？
- 是否完成？用时体感？
```

首页还可加 **第一印象题**（看 3–5 秒）：「这是做什么的？你能在这干什么？」——对齐大爆炸理论。

## 3. 环境

- 真站、预发、或可点原型均可；保真度够完成任务即可
- 录屏/记笔记二选一要有；两人时可一人主持一人记
- 移动与桌面分开任务或分场，避免混着比

## 4. 招募

- 优先 **像真实用户的人**，不必等完美抽样
- 回避：项目组成员当唯一用户（可作彩排，不作结论）
- 说明时长（常 30–60 分钟）、报酬/感谢、远程或现场

## 5. 主持要点

**做：**

- 请对方 **出声思维**
- 问「你在看什么 / 接下来打算怎样？」
- 卡住时等一等；再中性追问

**不做：**

- 辩护设计（「其实你应该点那里」）
- 过度示范或抢鼠标
- 把测试变成销售演示或引导问卷「你喜不喜欢蓝色」

善意提醒：礼貌与安全感 > 榨取吐槽。

## 6. 记录什么

优先记 **行为障碍**：

| 类型 | 例子 |
|------|------|
| 找不到入口 | 四处扫、点错栏目 |
| 误解标签 | 点了 A 期望是 B |
| 恢复失败 | 走错后回不来 |
| 假完成 | 以为成功其实没提交 |

少记：纯审美偏好、与任务无关的功能许愿清单。

## 7. 复盘与修修补补

会议极短、极狠：

1. 每人列出看到的问题（不争论）
2. **严重度**：阻碍核心任务 > 造成明显延误 > 小摩擦
3. 合并重复项
4. **本轮只认领能修完的 Top 问题**（常 3–10 个量级，视产能）
5. 其余进 backlog，下一轮再测验证

输出：

```markdown
# 可用性测试复盘

**日期/原型版本**: …
**参与用户数**: …
**核心任务**: …

## Top 问题（先修）
1. **[严重度]** 现象 → 影响的任务步骤 → 建议改法 → 负责人

## 观察摘要
- 做得顺的：…
- 反复卡住的：…

## 本轮明确不修
- …（及原因：低频/成本/待验证）

## 下一轮
- 验证点: …
- 预计时间: …
```

## 与空辩的关系

喜好之争（「我觉得用户会喜欢…」）用测试打断：

- 把争论写成 **可观察任务**
- 看用户做什么，而不是谁职级高
- 测试不能代替产品决策，但能减少「口味当论据」

## 反模式

- 等「完美原型」再测
- 一次测很多人却不修、只做报告
- 问卷满意度代替观察任务
- 主持人不断提示正确路径
- 把「用户没看帮助」当成用户错

## 边界

- 本 skill 是 **DIY 定性可用性质检**，不是眼动实验室或大规模量化研究
- 涉及隐私/录屏需取得同意；不收集与任务无关的敏感数据
- 无障碍专项测试需另补（本流程可顺带发现明显障碍，但不宣称 a11y 合规）
